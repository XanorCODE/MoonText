## 🐞 Сообщить об ошибке

Проще всего нажать **«Сообщить о проблеме»** в «Настройки → О программе»: версия, Windows, текущий трек, настройки и журнал скопируются в буфер и откроется страница нового issue, останется вставить данные (Ctrl+V). Или откройте [новый issue](https://github.com/XanorCODE/moontext/issues/new) сами и напишите:

- **версию MoonText** (в «Настройки → О программе») и версию Windows;
- **плеер**, в котором играет музыка (Spotify, Яндекс Музыка, браузер и другие);
- **трек**, на котором ошибка (исполнитель и название), если проблема с текстом;
- **что ожидали и что получилось**, по возможности со скриншотом или короткой гифкой;
- шаги, как это повторить.

> [!TIP]
> Если текст не нашёлся, сначала проверьте, есть ли он на [lrclib.net](https://lrclib.net). Если сервис отвечает ошибкой 429 («слишком много запросов»), подождите минуту и попробуйте снова: это ограничение самого LRCLIB, а не ошибка MoonText.

## 💡 Предложить идею

Опишите в issue, **какую задачу** вы хотите решить, а не только готовое решение. Так проще понять, нужна ли новая функция или подойдёт то, что уже есть. Если идея про внешний вид (новый дизайн оверлея, анимация плашки), приложите набросок или пример.

## 🛠 Запуск проекта

Нужны [Node.js](https://nodejs.org) 18 или новее и Windows 10/11: MoonText читает системный медиа-сеанс Windows.

```bash
git clone https://github.com/XanorCODE/moontext.git
cd moontext
npm install
npm start
```

Без плеера интерфейс можно проверить на тестовом треке:

```bash
MOONTEXT_FAKE=1 npm start
```

В PowerShell: `$env:MOONTEXT_FAKE=1; npm start`.

| Команда | Что делает |
|---|---|
| `npm start` | запускает приложение из исходников |
| `npm run pack` | собирает папку с программой без установщика (быстро, для проверки) |
| `npm run dist` | собирает установщик в `dist/` |
| `npm run icons` | пересобирает иконки из исходника |

Окно приложения (`src/`) — обычная веб-страница, поэтому интерфейс можно открыть и в браузере через любой статический сервер: в демо-режиме он покажет тестовый текст.

## 🗺 Как устроен проект

```text
main.js            главный процесс: окна, настройки, трей, обновления
preload.js         мост между окном и главным процессом
main/
  media.js         запуск и разбор вывода native/media.ps1
  lrclib.js        поиск и кэш текстов (LRCLIB), сохранение правок
  genius.js        запасной источник текстов
  cover.js         обложки (iTunes)
  accent.js        цвет обложки для подсветки текста
  stream.js        локальный сервер для оверлея в OBS
native/media.ps1   чтение медиа-сеанса Windows (SMTC)
src/
  index.html       разметка окна, styles.css — его оформление
  app.js           окно приложения: вкладки, остров, фон, визуализатор
  editor.js        редактор текстов и синхронизация
  engine.js        общий движок: строки, слова, часы
  pill.*           плашка рядом с панелью задач
  overlay*         оверлей для OBS
```

## 🔀 Pull request

1. Сделайте fork и создайте ветку от `main`: `git checkout -b fix-short-name`.
2. Вносите изменения небольшими коммитами. Одна задача — один pull request.
3. Проверьте, что программа запускается, а ваша правка работает (см. чек-лист ниже).
4. Откройте pull request и коротко опишите, **что** и **зачем** изменено. Для внешних изменений приложите скриншот.

### ✅ Чек-лист перед отправкой

- [ ] приложение запускается (`npm start`), в консоли нет новых ошибок;
- [ ] правка проверена на тёмной и светлой теме, если она касается интерфейса;
- [ ] оверлей и плашка не стали заметно тяжелее: MoonText работает в фоне, и расход процессора важен;
- [ ] не добавлены ключи, токены, личные данные и лишние зависимости;
- [ ] если меняется поведение, добавлен пункт в `src/changelog.js`.

## 🔒 Что учитывать

- **Тексты песен** загружаются из сторонних сервисов (LRCLIB, Genius) и хранятся только на компьютере пользователя. Не добавляйте в репозиторий сами тексты песен и их большие фрагменты, в том числе в тестовые данные и скриншоты.
- **Сеть.** MoonText обращается только к `lrclib.net`, `genius.com`, `itunes.apple.com` и `github.com`. Новые адреса нужно обосновать и добавить в раздел «Что уходит в сеть» в README.
- **Конфиденциальность.** Никакой телеметрии, аккаунтов и отправки данных о прослушивании. Визуализатор читает звук компьютера только внутри программы: он не записывается, не сохраняется и никуда не уходит.
- **Нагрузка.** Анимации (фон, визуализатор, остров) должны засыпать, когда музыка на паузе, окно свёрнуто или вкладка скрыта. Не вешайте покадровые циклы на `requestAnimationFrame` без паузы: на мониторах 144–240 Гц они работают в разы чаще.
